Systems I built at work#

The two production systems I own at HiAcuity, drawn honestly — including the parts that exist only because the naive version didn't hold up.

1. Multi-tenant candidate search

100K+ profiles · sub-second · MongoDB Atlas Vector Search + Voyage AI

recruiter query (natural language)
      │
      ▼
LangGraph reasoning step ── splits hard constraints from semantic intent
      │
      ├──► MongoDB filters         years · skills · location · tenant
      │
      └──► Atlas Vector Search     résumés chunked, max-pooled → 1 vector per profile
                │
                ▼
        Voyage AI rerank           the shortlist only — never the corpus
                │
                ▼
        ranked candidates          sub-second across 100K+ profiles

Design decisions that matter:

  • Why max-pool the chunks? One candidate should be one result. Chunk-level scoring put ten fragments of the same résumé in the top ten.
  • Why split the query first? Hard constraints are cheap in MongoDB and expensive in a vector index. Filtering before searching is what keeps it sub-second — reranking the whole corpus never would have.
  • Where tenancy lives: at the filter layer, not the application layer, so a missing check can't leak another tenant's candidates.

2. AI interview & assessment agent

LangGraph state machine · live transcription · auditable scoring

live interview (Recall) ──► WebSocket transcription stream
      │
      ▼
LangGraph state machine ── one competency block at a time, fully replayable
      │
      ├──► fairness critic       screens each follow-up for bias BEFORE it's asked
      │
      └──► claim check           spoken claims vs. the candidate's own résumé
                │
                ▼
        structured assessment    auditable, comparable across candidates

Design decisions that matter:

  • Why a state machine, not a prompt chain? Follow-ups stay scoped to the competency being assessed, and the whole run is replayable. A flat chain is neither.
  • Why a critic node? A biased follow-up is unrecoverable once a candidate has heard it. Screening happens before it's asked, not in review.
  • Why structured scores? Free-text assessments can't be compared. Structured ones can be audited, aggregated, and challenged.
